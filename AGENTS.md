# U.S. English editorial standard

Use **U.S. English (en-US)** throughout original source documentation, README files, UI copy, product descriptions, code comments, tests, model output, release notes, and future agent-authored changes. Write **color, behavior, optimize, analyze, organization, authorization, license, center, gray, canceled, and modeled**. For Formula 1 material, write **tire/tires**. Review AI-written language before committing.

Use clear, concise language without unnecessary boilerplate. Existing architecture, product names, source-cited quotations, legal notices, exact external APIs and schemas, published identifiers, dependency names, and generated files must remain compatible. Do not mass-rename programmatic fields or alter third-party source text to enforce a writing convention; record and test any separate public-interface migration.

## Engineering process

Follow [Engineering Rules v1.0](docs/ENGINEERING_RULES.md) for risk-based review, dependency and overlap reconciliation, affected-code QA, exact-head integration checks, and distinct merge versus release authorization. Do not bypass security protections or lift sample-only Pilot HOLD without separate owner and school-administrator authorization.
